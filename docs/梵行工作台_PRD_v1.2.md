# 梵行工作台产品需求文档（PRD）

版本：v1.2 · 飞书应用与 SSO 需求确认版（接口与业务配置仍待冻结）  
日期：2026-09-16  
范围：统一工作台、经营看板、知识中心（问答）、报销助手、财务审核助手

## 0. 文档使用与确认状态

本文是统一平台的产品需求基线。第 2 节记录用户明确要求；其余流程细节为根据现有原型整理的设计要求，新增或未核实部分须按本节和第 15 节确认，不能当作已获业务认可。

- **已确认**：以飞书应用为正式使用入口、采用飞书 SSO 身份认证；四模块顺序、取消独立首页与协作模块、经营看板原生化、管理层/OP/普通员工的经营权限、知识问答为主、不开放知识上传、复用现有知识库。
- **建议待确认**：无经营权限用户默认进入知识中心、阶段性交付顺序、历史对话与停止生成的本期优先级。普通员工默认知识中心已做原型验证，不等于业务已单独确认。
- **现有实现，需核定正式版本**：报销政策阈值与预检分类、财务复核和打印前置条件、经营指标口径。代码与演示数据只能作为核对依据。
- **外部依赖未核验**：现有知识库的部署、鉴权、用户映射、权限过滤、会话和引用协议；真实经营/报销/财务数据源。用户已确认知识库建好，但尚未与统一平台联调。

文档可用于产品评审和任务拆分；身份、接口、业务规则及验收基准未关闭前，不应据此承诺所有模块生产上线。完整可执行需求应包含：编号、优先级、触发条件、输入、处理规则、输出/状态、异常、权限和验收依据。

## 1. 产品目标

将已分别形成的经营看板、知识库、报销和财务审核能力统一到梵行工作台。员工在飞书应用内使用同一套界面，经飞书 SSO 确认身份后进入获授权的功能，减少在独立产品间切换；各模块保留自己的业务规则与后端服务。

本次优先完成统一入口、原生页面、角色与数据范围控制，以及已有知识库的问答接入。以当前蓝白工作台为界面基准，经营看板采用工作台原生组件。

成功标准：用户能直接进入获授权的主要工作页面；普通员工看不到经营看板；OP 负责人只能获取本 OP 数据；知识问答复用已有知识库且遵守其访问权限；报销与财务审核中需要本人或财务确认的动作继续由人完成。

## 2. 已确认的产品决定

| 事项 | 要求 |
| --- | --- |
| 产品名称 | 梵行工作台 |
| 正式使用入口 | 集成在飞书应用内，员工从飞书进入梵行工作台 |
| 登录方式 | 使用飞书 SSO；不另设工作台用户名、密码与自注册入口 |
| 授权方式 | 飞书验证身份后，由服务端判断模块、角色、OP、知识和单据范围；登录成功不等于具有全部业务权限 |
| 导航顺序 | 经营看板 → 知识中心（问答）→ 报销助手 → 财务审核助手；过滤未授权应用后保留相对顺序 |
| 首页 | 不单独设置工作台首页或应用入口卡片页 |
| 默认页面 | 有经营权限时经营看板置顶；普通员工不展示经营页面。默认进入知识中心是当前设计建议，降级规则见第 5 节 |
| 经营看板表现 | 原生页面，统一导航、字体、样式和页面滚动；不嵌入独立网页 |
| 经营权限 | 公司管理层看全部；OP 负责人只看本人负责的 OP；普通员工不展示该入口与页面 |
| 知识中心 | 以对话窗口为主；统一现有知识库的用户问答前端 |
| 知识上传 | 不向工作台用户提供自主上传、导入或文档管理入口 |
| 移除功能 | 交流与协作、项目经营视界、工作台首页 |
| 知识库基础 | 用户已明确知识库已构建完成；本次复用已有能力，不重复建设知识库底座 |

“项目经营视界”指移除的独立模块；经营看板内原有的项目健康、预算执行和延期节点仍保留。

## 3. 本期范围与边界

### 3.1 平台目标范围

1. 四个模块的统一布局、导航及状态管理。
2. 飞书 SSO、飞书应用内入口及业务授权对接，经营权限同时落实到界面和服务端数据查询。
3. 经营看板原生化，保留现有指标、筛选和明细能力。
4. 知识问答前端接入已有知识库，处理对话、来源展示、授权和异常状态。
5. 延续现有报销与财务审核流程，将尚未接通的服务列为独立联调任务。
6. 明确演示和正式运行的边界，正式业务不得使用模拟结果冒充真实处理。

上述是平台目标，不能理解成“四个模块所有后端能力必须一次性交付”。建议 P0 为统一布局、可信身份、经营访问隔离和知识问答基本闭环；真实经营数据及报销/财务联调各自作为独立交付包。顺序待确认，任何模块接入真实数据前都必须完成该模块授权。

历史会话的查询/删除、停止生成等属于接入既有能力的候选项：维护方确认能力后再锁定本期范围；缺失时不得擅自扩展为重建后端任务。回答权限和来源真实性不允许作为延期项。

### 3.2 本期不包含

- 独立工作台首页、交流论坛和项目经营视界模块。
- 员工自主建设知识库、上传知识文档、修改知识权限或管理模型。
- 重建已有知识库的检索、索引和模型底座。
- 未经业务确认的自动报销提交、自动财务放行或自动打印。
- 新增统一管理员后台。第一期可对接已有组织与授权配置；如需新建管理界面，另立需求。

## 4. 用户与权限

### 4.1 权限矩阵

| 身份或权限 | 经营看板入口 | 经营数据范围 | 知识中心 | 报销助手 | 财务审核助手 |
| --- | --- | --- | --- | --- | --- |
| 公司管理层 | 展示 | 全公司，可筛选 OP | 按知识库授权 | 本人业务 | 另需财务授权 |
| OP 负责人 | 展示 | 仅本人负责的 OP | 按知识库授权 | 本人业务 | 另需财务授权 |
| 普通员工 | 不展示 | 无权获取 | 按知识库授权 | 本人业务 | 未授予财务权限时不展示 |
| 财务授权人员 | 根据是否兼具经营角色决定 | 财务权限不自动授予全公司经营数据 | 按知识库授权 | 本人业务 | 授权范围内的单据与操作 |
| 未验证身份或授权信息缺失 | 不展示 | 默认拒绝 | 正式环境要求登录并校验 | 正式环境要求登录并校验 | 默认拒绝 |

经营角色规则为已确认需求。财务权限沿用现有“财务专属”定位，具体审批主体、单据范围及操作分级需财务负责人确认。知识权限以已有系统为准，不能因为具有管理层或经营看板权限，就自动开放全部知识。

### 4.2 界面规则

- 普通员工不展示经营看板菜单、页面内容、概览卡片或常驻“无权限”占位页面。
- 普通员工默认页面采用第 5.1 节建议规则。点击工作台品牌区回到本人可访问的默认页面。
- 管理层与 OP 负责人默认进入经营看板；前者可选全公司或 OP，后者仅显示本人 OP，不提供跨 OP 选项。
- 服务端在每次访问时重新核验当前授权，撤权后拒绝新请求；前端收到撤权/会话失效结果或身份变更事件后，立即清理数据并进入仍有权限的页面。无操作的已打开页面多久感知撤权，须由第 15 节确认机制和时限，不把“立即”当作已有推送能力。
- 切换身份时不得残留上一身份的看板、已展开明细或加载中的响应。
- 演示身份选择仅用于本地预览，正式界面不允许用户自行选择授权角色。

### 4.3 服务端规则

1. 通过飞书 SSO 验证用户身份与企业归属，建立工作台服务端会话，再从可信授权记录取得角色和 OP 归属。
2. 每次查询均在服务端校验；不能依赖隐藏按钮或前端筛选。
3. 在读取和汇总前限制数据范围。同一范围必须覆盖指标、图表、项目、人员、详情及未来的导出。
4. 未登录拒绝访问；普通员工或跨 OP 请求拒绝访问；授权配置缺失默认拒绝。
5. 浏览器传入的角色、OP 或员工标识不能作为授权依据。
6. 多角色可叠加独立权限；管理层角色是否可由哪些人员授予，由企业管理规则确定。
7. 当前按“一个 OP 负责人对应一个 OP”实现；兼管多个 OP 的规则列入待确认事项，确认前不开放扩大范围。

### 4.4 飞书应用承载与 SSO（已确认产品前提）

**正式产品形态：员工打开飞书应用内的“梵行工作台”，完成飞书身份认证后直接使用获授权模块。** 飞书 SSO 和飞书应用内集成属于本期公共基础能力，不能放到各模块上线后的可选优化中。

结合现有网页代码，技术承载方案建议采用企业自建应用的网页应用能力，在飞书客户端内打开工作台。飞书官方指南列出了网页应用主页与重定向地址配置，以及客户端内登录的接入方式；具体采用流程由研发按当前开放平台文档确认。[飞书官方 Web 应用登录指南](https://www.feishu.cn/content/7317091221654224898)

“企业自建网页应用”是依据现有代码提出的实施方案；复用现有报销应用还是单独注册梵行工作台应用，需确认。当前需求不默认扩展为飞书小程序重写或聊天机器人。

#### 4.4.1 用户进入与使用流程

1. 员工从飞书的应用入口打开梵行工作台，业务页面在飞书应用内展示；无需日常跳转到独立外部工作台。
2. 工作台检查有效会话；已有有效会话时继续校验当前权限，无有效会话时走飞书 SSO。
3. 首次使用或授权失效时，按飞书实际要求完成必要的授权步骤；不承诺任何情况下都完全无授权提示。
4. 服务端验证登录结果、用户所属企业与可用身份，建立工作台会话，读取该用户的业务授权。
5. 根据可用模块生成导航并进入默认页：有经营权限进入经营看板；普通员工不出现经营入口，按默认页降级规则进入知识中心等获授权页面。
6. 四个模块共享工作台身份，不因切换模块要求员工再次填写另一套账户密码；知识库等下游服务由服务端完成合法用户映射与授权衔接。

#### 4.4.2 身份认证与业务授权的分工

| 层次 | 判断什么 | 要求 |
| --- | --- | --- |
| 飞书应用可用范围 | 哪些员工可进入应用 | 由企业应用管理员配置；与后端企业/成员校验配合，不能只依赖入口是否可见 |
| 飞书 SSO | 当前访问者是谁、属于哪个企业 | 通过可信认证流程验证，不接受浏览器自行声明的员工身份 |
| 工作台业务权限 | 可访问哪些模块、执行什么操作 | 管理层、OP 负责人、财务权限独立配置；普通员工不展示经营模块 |
| 数据范围 | 可读取哪个 OP、哪些资料或单据 | 服务端执行范围校验；引用、详情和未来导出遵守同一授权 |

飞书部门、岗位或部门负责人信息不能未经确认就直接等同于业务 OP 或 OP 负责人。角色可以基于已确认的组织规则或独立授权记录维护，但其来源、授予人和变更机制必须明确。飞书应用管理员身份也不自动授予全公司经营或财务业务权限。

#### 4.4.3 用户映射、会话与服务调用

- 工作台需维护稳定的企业/员工唯一标识与下游用户映射，明确标识作用域；不以姓名或前端提供的邮箱匹配后直接授予权限。
- 现有知识库可能拥有独立用户体系，需建立飞书用户到知识用户的可信映射；不能为实现“免二次登录”而统一使用全库管理员身份。
- 登录校验、令牌交换及必要的刷新由可信服务端按飞书支持的流程完成；应用密钥和长期凭证不写入前端代码、页面地址或浏览器存储。
- 登录回调只返回允许的工作台地址，并校验请求关联和有效性；过期或重复使用的登录凭据不得产生错误身份或无限跳转。
- 工作台会话有效期与飞书凭证有效期分别管理。会话失效后恢复登录，清理旧身份数据，重新读取权限；不能只刷新界面标签而沿用旧授权。
- 切换飞书企业、账号，或用户离职/停用、业务撤权后，清理该身份的缓存、会话内容和草稿；在已约定的发现机制和时限内停止访问。
- 用户登录凭据与调用企业资源所需凭据分开管理。应用可以读取某数据源不代表当前员工有权读取其中所有记录。

#### 4.4.4 飞书内的页面与运行要求

- 使用工作台自身的统一导航与原生模块，不在工作台内再次嵌套整套独立经营页面。飞书承载整个应用与经营模块的原生化并不冲突。
- 桌面飞书作为当前主要工作场景；移动飞书的本期功能范围、最低版本与附件/打印限制在发布前确认，不能仅凭浏览器窄屏预览认定已适配飞书移动端。
- 在目标飞书客户端内验证页面打开、返回、刷新、重新进入、知识流式回答、来源链接、报销附件选择及所需下载/打印操作。
- 工作台前端和后端需有实际可达的正式服务地址；当前 localhost 仅用于开发。飞书应用入口集成不等于已有知识服务、业务数据或工作台后端自动完成部署。
- 飞书外直接打开链接的行为建议为：无有效会话时提示从飞书打开，或经确认后使用飞书网页登录；无论采用哪种，不允许匿名绕过。外部浏览器登录是否支持列入 D-10，当前不承诺独立外部使用场景。

#### 4.4.5 应用配置与交付物

飞书应用配置纳入正式交付，不只是提交页面代码：

1. 确认应用归属企业、应用标识，以及复用现有应用或新建应用的选择。
2. 配置正式/测试环境的网页入口、适用终端主页、登录回调及所选客户端能力要求的域名配置。
3. 申请所需最小权限，配置测试用户、应用可用范围及企业审批/发布流程；未申请的字段不能作为必然可取的输入。
4. 记录角色与 OP 授权维护方式、下游用户映射和凭据管理责任。
5. 交付飞书内可打开的测试版本、三类经营角色及财务测试账号、SSO/模块联调记录和正式发布检查结果。

## 5. 信息架构与全局交互

### 5.1 主结构

工作台整体运行于飞书应用内。左侧为工作台标识、已授权的模块导航和当前飞书身份；右侧为当前模块内容。使用一套字体、颜色、按钮、表单和状态提示。经营看板不出现第二套应用导航或内层页面滚动框。

导航不再按业务办理、经营管理、知识协作分组，直接按既定顺序展示可用模块。

默认页建议按可访问应用的固定顺序选择：经营看板 → 知识中心 → 报销助手 → 财务审核助手。没有经营权限但有知识权限时进入知识中心；知识模块无授权时跳到下一个获授权模块。所有模块都无授权时展示“暂无可用应用”及管理员联系说明，不加载任何业务内容。

未登录与授权加载失败是不同状态：未登录进入飞书 SSO 流程，授权加载失败提供重试且不默认开放模块。一个模块的业务服务暂时故障不代表撤销权限，不应导致导航反复消失。

页面定位与浏览器行为：建议每个模块有可复制的同源地址，刷新、前进/后退恢复该模块；地址不能充当授权依据。当前原型只有页内状态切换，尚未实现模块地址。若直接访问无权页面，服务端拒绝取数，前端回到可访问默认页，必要时只给一次简短提示，不留下经营“无权限页”。是否将模块地址纳入首批交付，见第 15 节。

### 5.2 状态保留

- 在同一身份下切换模块，保留本次页面内未提交的输入和上下文。
- 身份或授权范围变化后，清理受影响模块的数据；退出登录清理会话内数据及本地草稿。正式草稿必须按企业、员工隔离。当前报销草稿使用统一浏览器会话键，不能直接用于多人正式账号切换。
- 刷新后恢复哪些草稿、筛选和历史，由各模块的数据持久化规则决定，不默认承诺所有状态恢复。
- 知识对话正式接入后的历史保存与删除，沿用已有知识库能力并经接口确认；当前演示只保留本页问题。

### 5.3 通用异常

区分加载中、无数据、没有权限、会话失效、服务失败和功能尚未接入。无数据不能显示为全部金额为零；失败不能显示为成功。可重试的动作提供重试入口，重复点击不得产生重复业务记录。

## 6. 经营看板需求

### 6.1 筛选与数据状态

### 6.1.1 数据完整性与历史查询

下列细节为接真实数据前必须确定的口径，不能套用模拟数据默认值：

| 问题 | 产品要求 / 待确认边界 |
| --- | --- |
| 空值与零 | 确认无业务记录才可显示 0；来源缺失或失败显示“暂无数据/待核实”，不得当作 0 纳入合计 |
| 部分数据失败 | 可展示已成功板块及各自更新时间；依赖失败来源的总额不显示为完整公司总额 |

| 源记录变化 | 重复记录、合同取消/冲销、红冲、预算变更和人员成本修正须有唯一标识和更正规则；规则未定前不能承诺完整经营对账 |

### 6.2 销售概览

| --- | --- |

| 净签约金额 | 汇总人工确认值；不自动减采购金额；未确认部分不进入合计，单独提示笔数 |
| 开票金额 | 按开票日期汇总 |
| 回款金额 | 按实际回款日期汇总 |
| 当前商机金额 | 包含“确保、争取”，排除“已签、战败”；随 OP 范围变化，不受月份筛选影响 |

### 6.3 项目健康

- 显示项目名称、所属 OP、人工预算执行、费用预算执行和交付状态。
- 人工实际成本按实际人天 × P 值计算，与同期人工预算比较；P 值单位与万元转换保持一致。
- 费用按截至期末累计费用 / 项目总费用预算计算；跨月查询不得重复累加总预算。
- 无有效预算时展示“待确认”，不计算错误比例。
- 期间计划完成但逾期未确认、或实际确认晚于计划日期的节点标记延期。
- 展开延期节点可查看节点名称、负责人、计划日期、实际确认状态和对应金额。

### 6.4 经营概览

- 展示预计确认收入、实际确认收入与差额。公司范围标题为“公司经营”，单 OP 范围为“OP 经营”。
- 阶段金额按阶段增量比例 × 净签约金额计算；累计比例先转为增量，避免重复确收。
- 预计按计划确认日期归属，实际按已确认状态和实际日期归属；差额为预计减实际。
- 差额明细可区分本期计划未实现和其他期间在本期补确认的节点，明细净额应等于汇总差额。
- 成本分为项目费用、OP 费用和经营费用，保留费用项目与小计；避免明细、小计重复相加。
- 闲置成本按闲置人天 × P 值计算，展示人员明细；已包含在成本合计中的闲置金额不再次叠加。
- 成本来源、核算边界与分摊口径需业务确认后对接真实数据；当前模拟值不作为财务规则依据。

## 7. 知识中心（问答）需求

### 7.1 定位与已有资产

知识中心是员工面向已有企业知识库的问答窗口。已有代码由用户提供：<https://gitee.com/wuhan_rui_yi_zhixiang/fx-agent>。

现有系统完成状态以用户说明为基础。本次已知存在知识问答相关前端及接口调用实现，但尚未完成新工作台与该服务的实际联调。接口地址、认证方式、部署环境、历史会话与引用字段，以现有服务维护方提供的契约为准，不在 PRD 中虚构新接口替代现有能力。

### 7.2 用户主流程

1. 用户进入知识中心，看到主对话窗口、问题输入框和少量示例问题。
2. 输入问题或选择示例问题，发送后立即展示本人问题和回答生成状态。
3. 后端在该用户知识授权范围内检索、生成回答；前端按已确认的流式协议逐步展示。
4. 回答附带可核验来源；点击来源时再次校验阅读权限。
5. 用户继续追问，沿用当前会话上下文；新对话创建独立上下文。
6. 如本期确认接入历史会话，读取、保存和删除复用已有服务；支持范围及保留期在联调前确定。未包含该能力的首批交付不得展示可用的历史入口。

### 7.3 前端范围

| 功能 | 要求 |
| --- | --- |
| 主界面 | 对话区占主要空间，输入区位置稳定；不以文档列表或资源门户作为首页 |

### 7.4 权限与失败处理

- 飞书登录身份需经服务端正确映射到现有知识库用户；禁止所有人共用一个拥有全库权限的检索身份。
- 知识授权与经营授权独立判断；OP 数据隔离不能替代知识文档授权。
- 禁止在回答、引用、搜索片段或历史会话中泄露用户无权访问的内容。
- 无相关资料时明确告知未找到依据；检索失败与没有资料分别呈现。
- 会话失效要求重新登录；流式连接中断保留已显示内容并标明未完成，重试不得重复创建同一条用户问题。
- 尚未连接服务时只展示接入状态，不生成假回答，不声称问题已发送至企业知识库。

| 能力 | 平台需要的最小信息 | 对接验收 |

| 用户与知识范围 | 企业用户唯一标识到知识用户的映射、可用知识范围、未授权错误 | 至少两名权限不同的测试用户，无法互读资料、来源及会话 |

| --- | --- | --- |

引用查看不等于开放资料库管理：允许阅读获授权引用，知识上传、批量导入和管理入口仍不开放。敏感原文下载是否允许需另行确认。

### 8.3 提交与失败状态

草稿 → 预检 → 待本人确认 → 提交中 → 已提交（收到业务单号）或失败/结果待确认。阻断项未消除不能进入提交；可人工复核项应在本人确认前显著展示，并将核查状态随单提交。

提交超时且结果未知时先查询原请求状态，再决定是否重试，不能生成第二张单据。修改关键字段或附件后，受影响的预检结果必须失效并重新检查。撤回、退回修改和再提交的具体规则复用审批系统，不能由工作台另建冲突的审批状态。

## 9. 财务审核助手需求

沿用财务专属工作区，保持“问题核查 → 人工复核 → 打印确认 → 打印与归档”的责任边界。

- 展示授权单据、材料、具体风险点和辅助审核建议。
- 审批状态、模型建议、人工复核状态、打印确认状态和打印任务状态分别保存。
- 辅助建议为通过也不能直接打印；仍须完成要求的人工复核及打印确认。
- 发现问题或挂起时填写说明，不静默放行。
- 人工确认关联材料版本。新增或更换材料、撤回、驳回等情况使旧确认失效。
- 正式打印需要防重、任务状态和实际完成回执，点击确认不等于已经出纸。
- 财务人员的可见单据、主体及打印操作范围由服务端授权控制。

当前已具备演示流程和状态约束；真实单据、模型服务、PDF 生成、归档与打印需逐项对接验收。

### 9.1 状态与并发要求

| 维度 | 关键规则 |
| --- | --- |
| 人工复核 | 待复核 → 可打印 / 暂不打印；辅助建议非通过或选择暂不打印时填写说明；复核不等于修改外部审批状态 |
| 材料版本 | 复核和打印确认绑定同一材料版本；发现版本变化即拒绝旧确认并要求重新复核 |
| 打印确认 | 仅在有效复核、版本一致及业务状态允许时接受；服务端再次核验，不能只依赖按钮禁用 |
| 打印任务 | 至少区分未发送、已受理、处理中、完成、失败、结果未知；确认记录与实际任务分开保存 |
| 并发与重试 | 两人同时复核要检测版本冲突；重复确认或网络重试不创建重复打印任务；结果未知先查任务，不能盲目补打 |
| 审批条件 | 正式允许哪些审批状态打印，须财务负责人确认；当前演示的 pending 状态不能直接定为正式规则 |

已送达打印设备的任务不保证可撤销；撤回或材料变化发生在发送后，应阻止后续发送并记录待处理事件，不能显示“已取消出纸”。谁可补打、补打理由和纸质材料处置列入财务运行规则。

### 13.3 验收证据与发布条件

每个已纳入交付包的需求，必须关联实际测试账号/授权、输入样本、预期结果、测试环境版本和验收记录。不能把本地模拟身份或合成数据测试作为真实登录、知识权限与审批接入的证据。

- 业务负责人确认产品范围与业务口径；知识维护方提供授权问答样本及期望来源；财务提供票据边界样本；经营数据负责人提供可对账样本。具体人名待分配。
- 样本至少覆盖正常、缺失、无权限、边界日期、并发或重试等适用情形。问答质量以经确认的题目与来源集评估，不能只检查“返回了一段文字”。
- 各交付包上线前必须通过相关权限测试、数据/状态核对及真实服务联调；未接通模块隐藏正式操作或明确不可用，不允许回退为模拟成功。
- 性能目标、问答可接受质量、并发量、知识响应首字/完成时延、超时重试及撤权时限须在相应包冻结前填入数字与测试条件。当前未具备基线，不编造已达标数值。
- 若真实接入出现严重范围或数据错误，应可关闭对应模块的数据/操作入口并回到可用页面，保留其他模块；回退不自动撤销已提交审批或已发送打印。

## 14. 非功能要求

- 授权与会话：权限结果来自服务端；会话失效或撤权后按已确认机制及时生效。
- 缓存隔离：经营和知识响应不得被其他身份共享缓存；缓存键必须覆盖身份与授权范围。
- 可用性：桌面工作台优先，同时支持窄屏导航、输入和明细查看；不得造成页面整体横向溢出。
- 可访问性：表单有标签，主要操作可用键盘完成，状态不仅用颜色区分。
- 可追溯性：正式查询失败、业务提交、审核和打印应有可定位记录；日志不得直接记录完整敏感票据或未脱敏知识正文。
- 性能：加载时给出清晰状态，筛选变化只接纳最新请求结果；超时阈值与响应时延目标在接口联调后确认。
- 部署：演示与正式配置隔离，正式环境不得启用演示身份、样例审核成功结果或模拟打印回执。

## 16. 版本与评审结论

v1.0 保留为原始评审基线。v1.1 修正了确认状态和交付范围，补充默认页降级、历史数据口径、知识接入契约、报销字段及既有规则、财务状态与并发、实现差距和验收证据。

当前结论：产品方向和主要边界已明确，可以进入产品/接口联合评审与分包任务拆解。尚不能认定为覆盖所有模块的最终开发规格：D-01 至 D-10 应按各自最迟节点关闭，接口字段和政策阈值需经来源方确认。本次修订只更新产品文档，飞书 SSO 和应用配置尚未实际接通，不能将需求确认等同于代码完成。
