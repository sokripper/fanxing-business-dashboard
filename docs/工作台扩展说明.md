# 梵行工作台：界面与接入边界

## 本轮范围

本地工作台原型，复用已有个人报销规则与表单。财务数据为 `DEMO-*` 虚构示例，复核与打印确认仅留存在当前页面内存中。没有调用模型、外部查验、真实审批、飞书表格或打印机。切换助手保留本页填写；刷新后的个人草稿沿用原有“暂存本页”机制，财务演示重置。

## 扩展助手

`lib/assistant-registry.ts` 是独立的助手目录。名称、说明、受众分组、图标、主题、启用状态、展示顺序与入口都在目录内配置；首页、导航、筛选与助手数量从目录生成，不分别维护。

- 接入已有网页：增加 `entry: { kind: 'link', url: 'https://…' }` 条目。只接受无内嵌凭证的 HTTPS 地址，外链以独立窗口打开。
- 接入内置模块：单独实现组件，在 `components/workbench.tsx` 的 `modules` 中注册，再配置目录。现有个人表单、财务核查组件不需要为新助手改写。
- 尚未实现：设置 `status: 'planned'`；入口不可执行。
- 下线：设置 `enabled: false`，不会出现在入口或数量中。

新增入口不等于新增能力。新的助手若要连接模型、业务系统或读写数据，仍需自己的服务与授权校验。当前目录按代码配置维护，尚未实现在线管理员配置台。

## 数据边界

`lib/finance-preview.ts` 单独保存演示样例、数据类型和纯状态转换，组件只接收 `cases / onChange / selectedId / onSelect`。真实数据接入时替换数据提供层，不让组件直接读取凭证或拼接飞书请求。

正式服务必须分别维护：审批状态、模型建议、人工复核、打印确认与打印任务状态。金额以分存储；确认关联材料版本。材料改变、撤回、驳回后确认失效；后端再次核验，不信任前端按钮。打印任务需要幂等键、发送与完成回执，不能把点击确认当成出纸。

## 权限边界

当前“个人 / 财务”是助手分类筛选，不是身份切换或访问控制。所有数据都是演示数据，因此预览者可体验两个模块；未做真实 SSO。

正式上线后，飞书登录只确认身份。后端还需按员工、部门、付款主体和具体操作授权，每次查询、详情、下载、导出、回调和打印都要检查。助手目录的 `audience` 只供展示，不是授权依据；新助手不能继承财务权限。

## 未连接项

飞书登录与数据权限、真实报销创建/附件上传、OCR、外部验真/工商查询、模型审核、远程记录同步、实际 PDF 生成及网络打印均未在本轮接通。演示的“已复核”“已确认”不会提交任何审批或发送打印。

## 2026-09-16：统一应用工作台

沿用现有蓝白界面，应用目录按“业务办理 / 经营管理 / 知识协作”分组。报销、财务审核保持原交互与确认规则；新增经营看板、知识中心、交流与协作三个内置模块。首页分类和左侧导航由同一目录生成。

- 经营看板：在同一工作区中切换经营汇总与项目经营视界。`public/integrations` 内为既有两个模拟看板的本次快照，隔离嵌入，保留各自筛选与下钻；不是生产数据源，也不是实时飞书 Mock 联调。源页面更新后需要重新同步快照，两个看板的口径不自动合并。
- 知识中心：示例资料按共享、部门、个人分类，支持文本筛选与详情；问答区域明确显示未连接，问题只保留在本页，不生成伪造的模型回答。示例数据独立维护于 `lib/knowledge-preview.ts`。
- 交流与协作：示例话题支持分类、搜索、详情、新建和回复；新增内容只在当前页面内存中，切换应用保留，刷新重置；不发布到真实论坛或同步入库。
- 当前未迁移或修改 FX-Agent 仓库，也未改变其技术栈。后续在保留本工作台体验的前提下，按现有知识库接口接入身份、资料、问答及会话。

新增代码没有真实凭证、企业资料、远程写入或发布操作。保持本地预览，未部署更新。

## 2026-09-16 导航与知识问答调整（当前范围）

本节覆盖之前的首页、知识资料与协作入口规划。

- 导航固定为：经营看板 → 知识中心（问答）→ 报销助手 → 财务审核助手。
- 默认进入经营看板；移除工作台首页、返回首页按钮及交流与协作入口。
- 经营看板只加载经营汇总看板，不再加载项目经营视界。
- 知识中心直接进入对话窗口，提供示例问题、问题输入、当前页面对话和新对话；不提供用户上传、文档管理及资料列表入口。
- 现有知识库后端尚未接入此页面，点击发送仅保留本地问题并说明连接状态，不生成示例答案；切换模块保留当前内容，刷新后清空。
- 报销与财务审核流程沿用原有实现；后续知识库接入需对接实际身份、权限、流式问答与引用来源。

## 2026-09-16 原生经营看板与数据权限（当前实现）

- 经营看板现为 React 原生模块，沿用工作台导航、字体、蓝白样式和页面滚动。保留期间与 OP 筛选、销售指标切换、项目预算/延期节点、确收差额、成本及闲置人员明细。
- 移除 public/integrations 下两个旧 HTML 副本，原独立看板地址返回 404；原始项目资料保持不变。
- 用户确认的访问规则：公司管理层可看全部并筛选 OP；OP 负责人只可访问本人负责的 OP；普通员工、未登录、角色或 OP 未配置的账号默认拒绝。
- `/api/operations` 服务端在读取与汇总前校验身份和范围；OP 越权请求返回 403，未验证身份返回 401。响应禁用共享缓存，客户端身份切换时立即清除旧结果并取消在途请求。
- 本地开发环境提供明确标记的“权限演示”身份选择，且只在回环地址生成模拟数据。正式环境禁用 preview 参数，不能用客户端选择角色或伪造请求头获得授权。
- 正式企业身份尚未接通：`getVerifiedEmployee` 当前返回 null，实际访问默认拒绝。接入时必须验证飞书/公司会话，再由服务端授权记录获得 management / op-lead / employee 角色及 OP 归属，不能从 URL、请求头或 localStorage 读取授权角色。
- 真实经营数据源尚未接入：通过真实身份授权后仍返回 503，直到接上按授权范围查询的业务数据源；不会用模拟值伪装真实数据。未来查询、明细、导出均需复用相同授权范围。
- 已检查：公司汇总与各 OP 合计一致；OP 响应不含其他 OP 的汇总、项目、人员或明细；普通员工与跨 OP 请求被拒绝；伪造身份头被拒绝；旧公开页面不可访问。

## 2026-09-16 普通员工隐藏经营模块

普通员工不展示经营菜单、页面或权限占位，默认进入知识中心；管理层与 OP 负责人保留经营入口。服务端为首页提供经营权限结果，默认无授权；本地演示身份控件移至工作台侧栏。切换到普通员工会卸载经营模块，取消在途请求并清理旧数据。详细产品范围与验收见《梵行工作台_PRD_v1.0.md》。
